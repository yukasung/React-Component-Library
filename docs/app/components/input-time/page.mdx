# InputTime

InputTime คือ input สำหรับกรอกและแก้ไขเวลา พร้อมรายการเวลาแบบ dropdown ให้เลือกได้

### value

<PropertySignature name="value" type="Date | null" />

กำหนดค่าปัจจุบันของ control

<ValueDemo />

```tsx
const [value, setValue] = useState<Date | null>(new Date())
<InputTime value={value} onChange={setValue} />
```

<Callout type="info">
  **Note**

  ค่าจะถูกประมวลผล (parse, จำกัดช่วง, และยิง onChange) เฉพาะตอนออกจากฟิลด์ (blur), กด Enter, เลือกจากรายการ, กดปุ่มลูกศร หรือเลื่อนล้อเมาส์เท่านั้น — ไม่ใช่ทุกครั้งที่พิมพ์ ทำให้พิมพ์ข้อความที่ยังไม่สมบูรณ์ได้โดยไม่ถูกบล็อกระหว่างทาง
</Callout>

#### ส่วนวันที่ของ value

value เป็น `Date` เต็ม แต่ control นี้อ่านและเขียนเฉพาะ**ส่วนเวลา**เท่านั้น เมื่อมีการเปลี่ยนเวลา ส่วนปี/เดือน/วันของค่าเดิมจะถูกเก็บไว้ตามเดิม (ถ้าค่าเดิมเป็น null จะใช้วันที่ของวันนี้) จึงใช้ InputDate กับ InputTime คู่กันเพื่อประกอบเป็น `Date` ก้อนเดียวได้

วินาทีและมิลลิวินาทีจะถูกตัดออกเสมอ — control นี้ทำงานที่ระดับความละเอียดเป็นนาที

### placeholder

<PropertySignature name="placeholder" type="string" />

กำหนดข้อความที่แสดงเป็น hint เมื่อ control ว่างเปล่า

ถ้าไม่ระบุ จะแสดงรูปแบบของ format นั้นเป็นขีดล่างแทน — `__:__` สำหรับ format เริ่มต้น (`H:i`) และ `__:__ __` เมื่อ format มีตัวระบุ AM/PM (เช่น `h:i K`) จึงบอกผู้ใช้ได้ว่าช่องนี้รอข้อมูลรูปแบบไหนโดยไม่ต้องเขียน placeholder เอง

<Callout type="info">
  **Note**

  ต้องตั้ง isRequired เป็น false ด้วย ไม่เช่นนั้นฟิลด์จะไม่มีทางว่างเปล่า (บังคับแสดงเป็นเวลาเสมอ) และจะไม่เห็น placeholder เลย
</Callout>

#### การกรอกเป็นกลุ่ม

เมื่อคลิกหรือ tab เข้าไปในช่อง เนื้อหาจะถูกแบ่งเป็นกลุ่ม (ชั่วโมง / นาที / AM-PM) และกลุ่มที่คลิกจะถูกไฮไลต์ทั้งกลุ่มให้พิมพ์ทับได้ทันที (tab เข้ามาจะเริ่มที่กลุ่มแรก) ทุกกลุ่มจองที่ของตัวเองไว้ตลอด กลุ่มที่ยังไม่ได้กรอกจะแสดงเป็นขีดล่าง จึงกรอกนาทีก่อนชั่วโมงได้ — `__:35` เป็นสถานะที่มีจริง:

```
คลิกที่กลุ่มนาที → __:__   พิมพ์ 3 → __:03   พิมพ์ 5 → __:35
```

ตัวเลขถูกเติมศูนย์ข้างหน้าทันทีที่พิมพ์ (`1` → `01`) แต่กลุ่มนั้นยังรับหลักที่สองต่อได้ — พิมพ์ `4` ต่อได้ `14` ส่วนกลุ่มที่กรอกจบแล้ว การพิมพ์เลขใหม่จะเริ่มค่าใหม่ (`14` แล้วพิมพ์ `5` ได้ `05`)

| ปุ่ม | ผล |
|---|---|
| ← → | เลื่อนไปกลุ่มก่อนหน้า/ถัดไป |
| Home End | ไปกลุ่มแรก/กลุ่มสุดท้าย |
| ตัวคั่น (เช่น `:`) | ไปกลุ่มถัดไปและไฮไลต์รอพิมพ์ทันที ปิดค่ากลุ่มที่ออกให้ตามที่กรอกไว้ (กลุ่มว่างก็ข้ามได้) |
| Backspace Delete | ล้างกลุ่มที่ไฮไลต์ ถ้าว่างอยู่แล้วจะถอยไปล้างกลุ่มก่อนหน้า (ล้างได้จนหมดทุกกลุ่ม แม้ isRequired เป็น true — ค่าจะกลับมาตอนออกจากช่อง) |

กลุ่มที่กรอกไว้หลักเดียวจะถูกปิดค่าเป็นค่านั้นเองเมื่อเลื่อนออกจากกลุ่ม (`1` → `01`) และถ้าออกจากช่องตอนที่ยังมีกลุ่มไม่ได้กรอก ค่าจะไม่ถูกบันทึก ช่องกลับไปแสดงค่าเดิม — เวลาที่กรอกครึ่งเดียวไม่ใช่เวลา และ control จะไม่เดาส่วนที่ขาดให้

<Callout type="info">
  **Note**

  format ที่ไม่เติมศูนย์ (เช่น `h:i K` ที่แสดง `2:30 PM`) จะเติมศูนย์ขณะกำลังกรอก (`02:30 PM`) เพราะตำแหน่งของแต่ละกลุ่มต้องอยู่นิ่งระหว่างแก้ไข พอออกจากช่องจะกลับไปแสดงตาม format เดิม
</Callout>

<InputTime isRequired={false} defaultValue={null} format="h:i K" />         // __:__ __
<InputTime isRequired={false} defaultValue={null} placeholder="เวลานัดหมาย" />

<PropertySignature name="max" type="Date | null" />

<PropertySignature name="step" type="number | null" />

จำนวนนาทีระหว่างแต่ละรายการใน dropdown ค่าเริ่มต้นของ property นี้คือ 15 นาที

<StepDemo />

step ยังเป็นเงื่อนไข**เดียว**ที่กำหนดว่าจะมี dropdown หรือไม่ด้วย — ตั้งเป็น `null` (หรือค่าที่ไม่เป็นบวก) หมายถึงไม่มีระยะห่างที่นิยามไว้ จึงไม่มีรายการให้แสดง ปุ่มเปิดรายการจะถูกซ่อน และปุ่มลูกศร/ล้อเมาส์จะไม่ทำงาน เหลือเป็นช่องกรอกเวลาด้วยการพิมพ์อย่างเดียว

<NoStepDemo />

```tsx

```

<Callout type="info">
  **Note**

  ปุ่มลูกศรขึ้น/ลงจะเลื่อนไป**รายการถัดไป/ก่อนหน้าในรายการ** ไม่ใช่การบวกลบนาทีดิบ ๆ ดังนั้นค่าที่ไม่ตรงกับรายการใด (เช่น 09:07 เมื่อ step เป็น 15) จะถูกดึงเข้าหารายการที่ใกล้ที่สุดในทิศทางที่กด

  ขณะที่รายการเปิดอยู่ ลูกศรจะใช้เลื่อนตำแหน่งที่ไฮไลต์ในรายการแทน (ลง = เวลาถัดไป) แล้วกด Enter เพื่อยืนยัน
</Callout>

### format

<PropertySignature name="format" type="string" />

รูปแบบการแสดงผลและพิมพ์เวลา ใช้ชุดตัวอักษรกำหนดตำแหน่งชั่วโมง/นาที ค่าเริ่มต้นคือ `"H:i"`

โทเค็นที่รองรับ:

| โทเค็น | ความหมาย | ตัวอย่าง (14:30 น.) |
| :---: | --- | --- |
| H | ชั่วโมงแบบ 24 ชั่วโมง (มี 0 นำหน้า) | 14 |
| h | ชั่วโมงแบบ 12 ชั่วโมง ไม่มี 0 นำหน้า | 2 |
| G | ชั่วโมงแบบ 12 ชั่วโมง มี 0 นำหน้า | 02 |
| i | นาที (มี 0 นำหน้า) | 30 |
| K | ตัวระบุ AM/PM | PM |

<FormatDemo />

```tsx
<InputTime format="H:i" defaultValue={new Date()} />
<InputTime format="h:i K" defaultValue={new Date()} />
<InputTime format="G:i" defaultValue={new Date()} />
<InputTime format="h.i K" defaultValue={new Date()} />
```

<Callout type="warning">
  **Note**

  รองรับเฉพาะโทเค็นในตารางข้างต้นเท่านั้น ยังไม่รองรับวินาที (S/s) — format ที่มีโทเค็นอื่นจะถูกละเว้นทั้งชุดและใช้ค่าเริ่มต้น `"H:i"` แทน

  และใช้ H คู่กับ K ไม่ได้ (เช่น `"H:i K"`) เพราะขัดกันในตัวเอง — ชั่วโมงแบบ 24 ชั่วโมงบอกอยู่แล้วว่าเป็นช่วงไหนของวัน ตัว AM/PM จึงไม่เหลืออะไรให้บอก ("14:30 PM" ไม่ใช่เวลาที่มีอยู่จริง) format แบบนี้จะถูกละเว้นและใช้ `"H:i"` แทนเช่นกัน หากต้องการ AM/PM ให้ใช้ h หรือ G เป็นตัวชั่วโมง
</Callout>

### text

### portal

<PropertySignature name="portal" type="boolean" />

ค่าเริ่มต้น `true` รายการเวลาจะแสดงผ่าน body portal เพื่อหลีกเลี่ยงการถูกตัดโดย overflow container
รายการเลือกเปิดด้านบนหรือด้านล่างตามพื้นที่ และปรับขนาดตาม viewport
ใช้ `portal={false}` เพื่อแสดงภายในฟิลด์ เช่น เมื่ออยู่ใน native dialog top layer
รายการแบบ portal คง local dark theme, สี `--rc-color-primary` และฟอนต์ของฟิลด์

### portalZIndex

<PropertySignature name="portalZIndex" type="number" />

ค่าเริ่มต้น `100000` เนื่องจากรายการเวลาแบบ portal เป็นลูกของ `<body>` จึงต้องเรียงชั้นกับ overlay ของ application เช่น modal/drawer ไม่ใช่กับฟิลด์ข้างเคียง ค่าเริ่มต้นนี้จึงอยู่เหนือชั้น overlay ทั่วไป ปรับค่าได้หากแอปกำหนดชั้น z-index เอง
